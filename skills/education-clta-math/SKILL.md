# 教育部专用 · CLTA学教评一致性教学设计（初中数学版）

> **关联技能：** `beike-zhuanyehua`（备课专业化 · CLTA完整技能包 ✅ 已部署，本技能为其数学学科专用版）

> **核心理念：** 以数理为基，以智算为翼，解万策之题，汇邱氏之智  
> **使命对齐：** 让每节数学课都真正以学生为中心，让每个学习目标都可测量、可达成

---

## 一、CLTA核心理念（三句话讲清）

```
学教评一致性 = 
  学生学什么（目标）
  + 教师怎么教（活动）
  + 如何证明学会了（评估）
  → 三者围绕同一目标闭环
```

### 与传统备课的根本区别

| 维度 | 传统备课 | CLTA专业化备课 |
|:----:|----------|----------------|
| 起点 | "今天要讲什么内容" | "学生今天要学会什么" |
| 目标 | "理解…掌握…"（笼统） | "能说出…能写出…"（可测） |
| 活动 | 教师讲授为主 | 学生任务驱动 |
| 评估 | 课后考试（滞后） | 嵌入教学（实时） |
| 中心 | 知识中心 / 教师中心 | **学习中心 / 学生中心** |

### 初中数学课堂的三个转变

```
教师主讲 → 学生主学（70%时间给学生做）
讲题训练 → 任务驱动（用问题链串联课堂）
一课一讲 → 目标达成（每节课有可测量的输出）
```

## 二、CLTA教学设计六步操作法（初中数学版）

### 第一步：课标分析（定方向）

**操作模板：**

| 分析维度 | 要回答的问题 | 初中数学示例 |
|:--------:|-------------|-------------|
| **课标摘录** | 课标原文怎么说？ | 《课标》："理解二次函数的性质，会用配方法确定顶点坐标" |
| **学什么** | 学生要学哪些知识/技能？ | 二次函数的开口方向、对称轴、顶点坐标；配方法 |
| **学到什么程度** | 用什么行为动词描述？ | 能"说出"开口方向，"写出"顶点坐标，"画出"图像 |
| **怎么学** | 通过什么方式学？ | 借助网络画板观察 → 小组讨论归纳 → 变式练习巩固 |

**初中数学专用动词表（替代笼统词汇）：**

| 笼统词 | 替换为可测动词 | 数学示例 |
|:------:|:-------------:|----------|
| 理解 | 说出、解释、举例 | "能说出二次函数顶点式的结构特征" |
| 掌握 | 写出、画出、求出 | "能写出圆的切线判定定理的证明过程" |
| 体会 | 比较、归纳、总结 | "能比较一次函数与二次函数图像的异同" |
| 感受 | 描述、列举 | "能描述生活中可用反比例关系描述的现象" |

### 第二步：教材分析（析素材）

**操作模板：**

```
教材是如何体现课标要求的？
  → [分析：教材用哪个情境、哪些例题来落实课标要求]

教材是如何遵循学生认知规律的？
  → [分析：从直观到抽象、从具体到一般的编排逻辑]
```

**初中数学示例（《分一分》分数初步认识）：**
```
课标要求：结合具体情境初步认识分数
教材编排：
① 分苹果情境 → 引出"一半"的概念（直观）
② 涂一涂、折一折 → 用图形表示1/2（操作）
③ 写一写 → 认识分数符号（抽象）
④ 找一找 → 在图形中找分数（应用）
→ 遵循从直观→操作→抽象→应用的认知规律
```

### 第三步：学情分析（找起点）

**操作方法：前测+数据分析**

```
① 设计前测题（3-5道）
② 实施前测（课前5分钟）
③ 统计正确率，找出薄弱点
④ 针对薄弱点制定教学对策
```

**初中数学前测示例（《一元二次方程》）：**

| 前测题 | 正确率 | 暴露的问题 | 教学对策 |
|:------:|:------:|-----------|---------|
| 什么是方程的解？ | 92% | 基础概念牢固 | 快速回顾 |
| 解方程：x² = 9 | 65% | 35%学生漏解x=-3 | 强调平方根有两个解 |
| 解方程：(x-1)² = 4 | 40% | 60%不会整体代换 | 用换元法引导 |
| 什么是因式分解？ | 55% | 45%遗忘十字相乘 | 课前5分钟复习 |

### 第四步：目标叙写（ABCD法）

**公式：**

```
在 [条件C] 下，[学生A] 能 [行为动词B] [内容]，[程度D]
```

**初中数学示例：**

| 序号 | 目标（ABCD写法） | 对应课标 |
|:----:|-----------------|:--------:|
| 目标1 | 给定二次函数y=ax²+bx+c，学生**能写出**顶点坐标和对称轴，**准确率≥90%** | 会用配方法 |
| 目标2 | 借助网络画板观察图像，学生**能说出**a的正负与开口方向的关系，**至少说出两条规律** | 理解性质 |
| 目标3 | 不借助任何工具，学生**能画出**y=x²、y=-x²、y=(x-1)²的示意图，**三图基本准确** | 数形结合 |

**验证目标质量（SMART原则）：**

| 维度 | 问题 | ✓/✗ |
|:----:|------|:----:|
| S（具体） | 目标描述的是学生的学习结果吗？ | |
| M（可测） | 能通过学生具体行为判断达成吗？ | |
| A（可达成） | 一节课内学生能完成吗？ | |
| R（相关） | 与课标要求一致吗？ | |
| T（时限） | 有明确的时间限制吗？ | |

### 第五步：评估任务设计（证明学会了）

**原则：每个目标对应一个评估任务**

```
目标1 → 评估任务1：学生完成什么行为就算达成了目标1？
目标2 → 评估任务2：学生完成什么行为就算达成了目标2？
目标3 → 评估任务3：学生完成什么行为就算达成了目标3？
```

**初中数学评估示例（《中位数和众数》）：**

| 学习目标 | 评估任务 | 评估方式 |
|:--------:|:--------:|:--------:|
| 能说出中位数和众数的定义 | 独立写出定义，并用数据举例说明 | 纸笔+小组互评 |
| 能求出一组数据的中位数和众数 | 给定3组数据（含偶数个数据、多众数情况），准确计算 | 当堂练习+巡视 |
| 能选择合适统计量分析实际问题 | 小组讨论并汇报：某公司工资数据，用哪个统计量描述？ | 小组展示+教师点评 |

### 第六步：教学活动设计（落实目标）

**九大教学事件简化为四个环节（适合初中数学课堂45分钟）：**

| 环节 | 时间 | 教学事件 | 初中数学示例 |
|:----:|:----:|:--------:|-------------|
| 一、激活导入 | 5min | 引起注意+告知目标+激活旧知 | 展示生活情境图："这家店该不该打折？"→呈现目标 |
| 二、探究建构 | 20min | 提供情境+指导学习+引出表现 | 小组探究：用网络画板拖动滑块观察函数图像变化规律 |
| 三、巩固检测 | 10min | 反馈评价+学习检测 | 变式练习：5道题独立完成+同伴交换批改+教师精讲 |
| 四、归纳迁移 | 10min | 保持迁移+小结梳理 | 用思维导图总结本节核心+布置分层作业 |

**课堂时间分配铁律：**

```
学生活动时间 ≥ 25分钟（占55%以上）
教师讲授时间 ≤ 15分钟（占30%左右）
评估时间 ≈ 5分钟（占15%）
```

### 4.0 AI诊断核心Prompt（学霸基本法诊断引擎 · V2.2 几何证明增强版 · 2026-07-20 生产版）

> **版本演进：** v6(07-06) → v7(07-09) → **v8(07-12)** → **V2.1(07-18)** → **V2.2(07-20)** 当前生产版本

**V2.2 相对于 V2.1 的核心改进（2026-07-20）：**

| 改进点 | V2.1 (07-18) | V2.2 (07-20) |
|--------|:------------:|:------------:|
| 几何证明检查 | 3条基础检查 | ✅ 三步11条全面检查（已知→求证→证明） |
| 已知条件分析 | 仅检查"是否写出已知" | ✅ 逐条检查：是否漏条件、是否误解条件含义（如"高相等"是哪两条高）、是否错误添加条件 |
| 求证目标检查 | 仅检查"是否正确" | ✅ 新增：是否把求证当已知用（循环论证检测） |
| 证明过程检查 | 仅三段式+判定/性质 | ✅ 新增：跳跃性表述、逻辑链完整性、中间结论→最终结论 |
| 几何变换 | ❌ 无 | ✅ 平移/旋转/轴对称对应元素关系检查 |
| 默认provider | deepseek-v4-flash | ✅ agnes-2.0-flash（DeepSeek API密钥过期） |

**几何证明题三步11条全面检查（V2.2）：**
```
第一步：检查已知条件（最易错！）
  a) 是否提取了所有已知条件？有无漏掉"高相等""中点""角平分线"等？
  b) 是否准确理解每个条件的数学含义？（如"高相等"——是哪两条高？能推出什么？）
  c) 是否错误添加了题目中没有的条件？（常见"想当然"错误）
  d) 涉及几何变换时，是否理解变换前后对应元素的关系

第二步：检查求证目标
  e) 求证目标是否与题目要求一致？
  f) 求证目标是否被学生错误地当作已知条件来使用？（循环论证——最常见逻辑错误）

第三步：检查证明过程
  g) 三段式书写规范（已知→求证→证明）
  h) 是否有"显然""容易看出"等跳跃性表述？
  i) 判定定理和性质定理是否混用？
  j) 逻辑链是否完整（先证中间结论，再用中间结论推最终结论）
  k) 是否存在循环论证——用结论去证中间步骤？
```

**纠正指导字段写作原则：**
- `corrective_guidance`：必须写具体的"怎么做"，不是笼统的"需要加强"
  - ✅ "严格遵循已知→求证→证明的三段式书写规范"
  - ❌ "需要加强证明题训练"
- `corrective_guidance_list`：1-3条综合性纠正指导，含具体书写规范或推理习惯要求

### 4.1 错因类型提取规则

后端 `_extract_error_types()` 方法（agent_service.py）从诊断文本中提取错因关键词：

1. 优先匹配六维标准名称：概念模糊、计算失误、审题偏差、思路中断、规范缺失、知识断层
2. 同时兼容旧版名称（告警不报错）：概念不清、审题不清、方法不当
3. 额外提取含"不理解""没有注意""混淆""漏了""忘记"的具体描述句（长度4-80字符）
4. 返回格式：`["概念模糊", "不理解角平分线定理"]`（错因类型 + 具体说明）

### 4.2 错因六维分类 → CLTA六步映射

| CLTA步骤 | 对应的错因类型 | 操作 |
|:--------:|:-------------|:-----|
| ①课标分析 | ⑥知识断层 | 课标要求"运用"层级的，学生前置知识缺失→知识断层 |
| ②教材分析 | ②计算失误 | 教材中的规范计算方法学生出错→需回归教材方法体系 |
| ③学情分析 | 全部6类 | 前测时标记学生各类型错因的分布占比 |
| ④目标叙写 | ⑤规范缺失 | 目标写清"能完整写出…的全部步骤"而非笼统"掌握" |
| ⑤评估任务 | ③审题偏差 | 评估任务中故意设计干扰条件，检测学生审题能力 |
| ⑥教学活动 | ①概念模糊 | 探究环节侧重概念辨析，用辨析题暴露概念边界 |

### 4.5 六维错因分类术语铁律（2026-07-14 董事会签发）

| ❌ 禁用写法 | ✅ 标准写法 | 原因 |
|:----------:|:----------:|:-----|
| 概念不清 | **概念模糊** | 「不清」口语化，不符合学术诊断标准 |
| 方法不当 | **计算失误** | 六维体系中合并为计算失误 |
| 步骤不完整 | **规范缺失** | 涵盖格式/步骤/书写规范 |
| 审题不仔细 | **审题偏差** | 「仔细」偏向态度，「偏差」偏向能力诊断 |
| 迁移不足 | **思路中断** | 更准确描述解题过程中的思维卡顿 |
| 运算错误 | **知识断层** | 六维体系新增此维度 |

> **执行：** CLTA诊断Prompt（agent_service.py）中 `error_type` 输出格式已全局修复为 `概念模糊|计算失误|审题偏差|思路中断|规范缺失|知识断层`。旧写法已在代码、前端JS、测试、文档中全部清理，零残留。

### 4.3 知识库联动系统（2026-07-07 新增 · 2026-07-19 LLM Wiki升级）

学霸基本法内置了两层知识库系统：

**第一层：SQLite/PostgreSQL `knowledge_base` 表**（2026-07-07），用于存储和复用历史错因模式，让诊断具有"记忆"。

#### 库表结构

```sql
knowledge_base (
    id, topic, error_type, error_pattern,
    correct_understanding, example_question, grade,
    version, hit_count, created_at, updated_at
)
```

#### 诊断增强机制

当用户提交新题诊断时，`LLMClient.diagnose()` 自动执行：
1. 从文本中提取关键词，调用 `session_manager.kb_search(topic=text[:20], limit=3)`
2. 匹配到历史记录时，在CLTA诊断prompt中追加一段「历史错因参考」
3. AI据此对比：本次错误是否与历史同类、同样是概念不清还是新类型

| 端点 | 方法 | 用途 |
|:-----|:-----|:------|

| `/api/v2/knowledge/add` | POST | 添加错因条目 |
| `/api/v2/knowledge/topics` | GET | 统计各知识点命中次数 |

### 9.2 JSON解析三阶降级（后端）

`agent_service.py` → `generate_practice()` 中：

```python
try:
    # 1. 先去代码块标记再直接解析
    cleaned = content.strip()
    if cleaned.startswith('```'):
        cleaned = re.sub(r'^```(?:json)?\s*', '', cleaned)
        cleaned = re.sub(r'\s*```$', '', cleaned)
    parsed = _json.loads(cleaned)
    questions = parsed.get("questions", [])
except Exception:
    try:
        # 2. 用贪婪正则匹配完整嵌套JSON（含多层{}）
        json_match = re.search(r'\{.*\}', content, re.DOTALL)
        if json_match:
            parsed = _json.loads(json_match.group(0))
            questions = parsed.get("questions", [])
    except Exception:
        pass
    if not questions:
        # 3. 截断至200字符，防超大原始内容溢出
        questions = [{"title": "巩固练习", "question": content.strip()[:200]}]
```

**关键陷阱：** 不能用非贪婪`[\s\S]*?`，遇到嵌套JSON只匹配第一个`}`导致解析失败。必须用贪婪`\{.*\}`+`re.DOTALL`。

### 9.6 前端硬超时与后端响应时间匹配（2026-07-19 实战发现）

② 检查前端setTimeout / AbortController → 20秒/35秒

### 9.7 后端JSON解析多层容错（2026-07-19 实战修复）

`generate_practice()` 的JSON解析从 **2层提升到4层**，与 `diagnose()` 看齐：

```python
# 1. 先找```json```代码块
json_match = re.search(r'```(?:json)?\s*(\{[\s\S]*?\})\s*```', content)
# 2. 找第一个{到最后一个}
first_brace = content.find('{'); last_brace = content.rfind('}')
# 3. 补全缺失括号（截断恢复）
jt += '}' * (jt.count('{') - jt.count('}'))
# 4. 仍失败则作为纯文本回退
```

**关键经验：** 诊断的 `diagnose()` 一直有6层JSON容错所以不出问题，但 `generate_practice()` 只有2层导致JSON截断时直接失败——**所有调用LLM返回JSON的地方必须用同样的多层容错**。

## 十一、运营陷阱与操作经验（2026-07-18 更新）

### 11.1 安全替换大段Prompt（重要！）

替换 `CLTA_DIAGNOSE_PROMPT` 这种大段多行提示词时，**切忌用行级替换或sed**。

**坑：** 直接用Python行列表构建新prompt并替换行区间，会无意删除prompt闭合引号之后所有代码（LLMClient类约430行）。

**安全做法：**
```python
# ✅ 用字符串匹配 + read()/write()
with open('agent_service.py', 'r') as f:
    content = f.read()
# 找到旧prompt边界
old_start = '# CLTA 学教评一致性 Prompt 模板'
old_end = '{text}\"\"\"'
start_idx = content.find(old_start)
end_idx = content.find(old_end, start_idx) + len(old_end)
# 替换
content = content[:start_idx] + new_prompt_str + content[end_idx:]
with open('agent_service.py', 'w') as f:
    f.write(content)
```

**验证：**
```bash
grep -n "class LLMClient\|def diagnose\|def diagnose_stream\|def generate_practice" agent_service.py
```
