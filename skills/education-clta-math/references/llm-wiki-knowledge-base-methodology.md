## 一、核心理念

### 不是存资料，而是编译知识网络

好学生和普通学生的区别不是谁做的题多，而是知识是否成网。  
LLM Wiki 不是"把教材上传给 AI"，而是把知识点逐步编译成——  
**可查询、可链接、可维护、可复习的 Markdown 知识网络。**

### 三层分离原则

```
待处理资料（_raw/）  ← 原始素材，不要求整洁，先存再说
   ↓ ingest
正式知识页面          ← 概念/方法/综合/参考，持续审核维护
   ↑ 规则约束
规则层（_meta/）     ← 标签词表、仪表盘，约束AI行为
```

### 慢启动、可验证、持续生长

不一次消化全部知识点。先跑通一个小范围闭环（如七上"有理数"），验证模板和流程后，再一章一章扩展。

> **起步时的目标，不是生成最多页面，而是建立第一批可信、可复用、能继续连接新知识的页面。**

## 二、目录结构模板

```
knowledge_base/
├── _raw/                        ← 知识收件箱（原始资料，按章节存放）
│   ├── 第1章 有理数.md
│   └── ...
├── concepts/                    ← 概念页（核心！60-80个核心概念）
│   ├── 有理数.md
│   └── ...
├── skills/                      ← 方法页（解题技巧，20-25个）
│   ├── 数形结合法.md
│   └── ...
├── synthesis/                   ← 综合页（跨章节专题，8-10个）
│   ├── 函数综合专题.md
│   └── ...
├── references/                  ← 参考页（公式表/目录）
│   ├── 七年级公式总表.md
│   └── ...
├── _meta/                       ← 规则层
│   ├── taxonomy.md              ← 标签词表（约束概念命名一致性）
│   ├── dashboard.md             ← 复习仪表盘（间隔复习状态）
│   └── template-concept.md      ← 概念页模板（AI生成用）
├── index.md                     ← 知识库地图（按章节索引）
├── log.md                       ← 审计日志（每次变更留记录）
└── hot.md                       ← 近期活动缓存
```

## 三、概念页模板（两篇文章一致）

```markdown
# 知识点名称

## 概念与定义
与课标对齐的标准定义

## 核心公式与性质
公式用LaTeX，性质分条列出

## 前置知识
学这个之前必须掌握什么，带 [[链接]] 指向其他页面
同时写入 frontmatter 的类型化关系（uses/extends）

## 常见题型
表格格式：题型 | 识别信号 | 参见方法页

## 常用方法
概念页不重复方法页完整内容，只写要点 + 链接

## 易错点
每条以 ❌ 开头，必须有学生实测依据
确有内容才打 #易错 标签

## 关联页面
水平关联（兄弟/相邻概念）

## 待核验项
自查清单，确保质量
```

### 模板各部分说明

| 区块 | 必填 | 说明 |
|:----|:----|:------|
| **frontmatter** | ✅ | 标题、年级、章节、标签、前置/关联关系 |
| **概念与定义** | ✅ | 与课标对齐的标准定义 |
| **核心公式与性质** | ✅ | 公式用LaTeX，性质分条列出 |
| **前置知识** | ✅ | 学这个之前必须掌握什么，带[[链接]] |
| **常见题型** | ✅ | 表格：题型→识别信号→参见方法页 |
| **常用方法** | ⚠️ | 指向skills/方法页，不重复内容 |
| **易错点** | ✅ | 每条以"❌"开头，必须有学生实测依据 |
| **关联页面** | ✅ | 水平关联（兄弟/相邻概念） |
| **待核验项** | ✅ | 自查清单，确保质量 |

## 四、方法页模板

解题方法页专注于"什么信号→用什么方法→怎么做"。

```markdown
---
title: 数形结合法
category: skill
tags: [思想方法, 代数, 几何]
applicable_to:
  - 函数图像题
  - 方程与不等式
  - 几何最值问题
---

# 方法名称

## 适用信号
题目中出现哪些关键词时优先考虑此方法？

## 基本步骤
1. 读题 —— 识别题目类型
2. 建系 —— 建立坐标系或画图
3. 转化 —— 代数条件 ↔ 几何图形
4. 求解 —— 利用图形发现关系
5. 验证 —— 结果代回原题

## 常见题型与示例
参见 [[synthesis/专题页面]]

## 易错陷阱
⚠️ 具体常见错误

## 关联概念
- [[相关概念页]]
```

## 五、初中数学知识库渐进路线（建议7轮）

| 轮次 | 章节 | 概念页 | 方法页 | 理由 |
|:----|:-----|:------|:------|:-----|
| 第1轮 | 有理数 + 整式 | 8-10 | 2 | 数与式是整个初中的基础 |
| 第2轮 | 方程与不等式 | 6-8 | 3 | 方程建模是核心能力 |
| 第3轮 | 函数 | 6-8 | 3 | 函数贯穿代数几何 |
| 第4轮 | 三角形与四边形 | 10-12 | 4 | 几何证明系统 |
| 第5轮 | 圆 | 5-6 | 2 | 综合性强 |
| 第6轮 | 概率与统计 | 4-5 | 1 | 相对独立 |
| 第7轮 | 综合专题 + 中考 | 8-10 | 5 | 跨章节整合 |

## 六、关键原则

### 命名一致性（防重复页面）
先用 `taxonomy.md` 定好词表，约束页面命名。  
不先规定 → AI今天写"函数的单调性"，明天写"单调函数"，后天写"函数增减性"。

### 类型化关系（知识图谱的边）
前置知识、关联页面在 frontmatter 中写入类型化关系：  
- `type: extends` = 父子关系（有理数 extends 自然数）  
- `type: uses` = 使用关系（二次函数 uses 配方法）

### 审计日志（每步可追溯）
每张页面的创建、每次链接补全、每次标签归一化都记录在 `log.md` 中。  
事后能精确说出"这个页面是哪天、因为什么产生的"。

### 先规定模板，再批量生成
没有模板 → 每页结构随机 → 知识库越来越难维护。  
正确的顺序：先定模板 → 跑通小范围 → 验证后扩展 → 批量生成。

### 源文件保留（待处理 ≠ 已处理）
`_raw/` 保留原始资料（即便已生成正式页面），作为溯源依据。  
正式页面有误时可以回头查原始资料。
